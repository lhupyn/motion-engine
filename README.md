# MotionEngine

> **Proof of concept** — This is an early-stage exploration of data-driven motion control for 3D avatars.

Motion engine plugin for [TalkingHead](https://github.com/met4citizen/TalkingHead) 3D avatars. Adds expressive, multi-layered motions (gestures + facial expressions + bone oscillation overlays) that go beyond TalkingHead's built-in animations.

**[Live Demo](https://lhupyn.github.io/motion-engine/)**

## Features

- **39 built-in motions** with synchronized facial expressions, gestures, and body movement
- **Bone oscillation overlays** (e.g., hand waving, hip bounce, laugh tremor) via `poseDelta`
- **Motion sequencing** — chain motions for multi-step animations
- **Motion interruption** — new motions cleanly interrupt running ones
- **LLM-friendly discovery** — `getMotions()` returns semantic descriptions and tags
- **Configurable timing** — all fade/settle durations are constructor options
- **Fallback** to native TalkingHead gestures, emojis, and poses
- **No DOM dependencies** — works as a pure plugin
- **Data-driven** — motions are pure JSON, no code changes needed to add new ones

## Why MotionEngine + LLMs?

TalkingHead ships with a fixed set of emoji animations and gestures. When an LLM controls an avatar, it needs a **semantic, extensible vocabulary** — not low-level blendshape values.

MotionEngine bridges that gap:

| Without MotionEngine | With MotionEngine |
|---|---|
| LLM picks from fixed emojis (`😊`, `👍`) | LLM calls semantic names (`celebrate`, `thinking`, `sigh`) |
| Wave = hand goes up and stays static | Wave = hand raises + oscillates + smile + eye squint (3 layers) |
| Adding motions requires JS code | Adding motions = adding JSON entries |
| Each animation is a single layer | Facial expressions + gestures + bone overlays synchronized |
| No body animations | Jump, dance, bow, turn — full body choreography |

**For AI agents**, this means:

- **Simple tool interface** — `engine.play("thinking")` instead of orchestrating 8 individual blendshapes.
- **Semantic discovery** — `engine.getMotions()` returns `[{name, description, tags}]` for LLM tool registration.
- **Data-driven extensibility** — `motions.json` is pure JSON. New motions can be authored (or generated by an LLM) without touching code.
- **Richer non-verbal communication** — MotionEngine's `celebrate` combines smile, raised hand, squinted eyes, and a hip bounce overlay — the LLM triggers all of this with one name.
- **Graceful fallback** — Unknown motion names are resolved against native TalkingHead gestures, emojis, and poses automatically.

## Usage

```js
import { TalkingHead } from 'talkinghead';
import { MotionEngine } from 'motion-engine';
import motions from 'motion-engine/motions';

// Create TalkingHead instance
const head = new TalkingHead(container, { /* options */ });
await head.showAvatar({ url: '/model.glb', body: 'F', avatarMode: 'full-body' });
head.start();

// Create engine with optional timing overrides
const engine = new MotionEngine(head, {
  gestureFadeIn: 800,    // default
  stopSettleTime: 1000,  // default
});
engine.registerMotions(motions);

// Hook into render loop for overlay oscillations
head.opt.update = (dt) => engine.update(dt);

// Play a motion
await engine.play('wave_right');

// Play a sequence
await engine.playSequence(['thinking', 'nod_yes', 'celebrate']);

// Discover motions for LLM tool registration
const available = engine.getMotions();
// → [{name: "wave_right", description: "Friendly wave...", tags: ["greeting", "friendly"]}, ...]
```

## API

### `new MotionEngine(talkingHead, options?)`

Create a new engine bound to a TalkingHead instance.

| Option | Default | Description |
|---|---|---|
| `gestureFadeIn` | `800` | Fade-in for gesture playback (ms) |
| `gestureFadeOut` | `800` | Fade-out when stopping a gesture (ms) |
| `stopFade` | `100` | Quick fade for interrupt stops (ms) |
| `stopSettleTime` | `1000` | Wait after stopGesture before cleanup (ms) |
| `poseFadeIn` | `1500` | Transition time for pose changes (ms) |
| `poseSettleTime` | `1700` | Wait after setPoseFromTemplate (ms) |
| `nativeDuration` | `3` | Default duration for native gestures (s) |

### `engine.registerMotions(motions) → number`

Register a dictionary of custom motions. Returns the number registered. Strips `_description`, `_tags`, and `_overlay` metadata before registering as `animEmoji`. Validates against `gestureTemplates` to prevent recursive loops.

### `engine.play(name, dur?) → Promise<void>`

Play a motion by name. Resolution order: custom → native gesture/emoji → pose. Interrupts any currently playing motion.

### `engine.playSequence(names) → Promise<void>`

Play an array of motions sequentially. Stops if `stop()` is called mid-sequence.

### `engine.stop()`

Force-stop the current motion with clean cancellation.

### `engine.getMotionNames() → string[]`

Get all registered custom motion names.

### `engine.getMotions() → Array<{name, description, tags}>`

Get full motion metadata for LLM tool discovery (~660 tokens).

### `engine.getMotionsCompact() → Object<string, string[]>`

Get motions grouped by primary tag — 75% fewer tokens (~164 tokens).

```js
engine.getMotionsCompact()
// → { greeting: ["wave_right", "wave_left", "namaste_bow"],
//     sarcasm: ["eyeroll", "smirk"],
//     frustration: ["facepalm", "sigh"], ... }
```

### `engine.getMotionsForPrompt(level?) → string`

Get a pre-formatted string ready for injection into LLM system prompts.

| Level | ~Tokens | Output |
|---|---|---|
| `'full'` | ~660 | `- wave_right: Friendly wave with hand oscillation...` |
| `'compact'` (default) | ~164 | `greeting: wave_right, wave_left, namaste_bow` |
| `'minimal'` | ~103 | `wave_right, wave_left, thumbup_right, ...` |

### `engine.update(dt)`

Frame update hook for oscillation overlays. Connect via:

```js
head.opt.update = (dt) => engine.update(dt);
```

### Callbacks

```js
engine.onStart = (name) => { /* motion started */ };
engine.onEnd = (name) => { /* motion finished */ };
engine.onError = (name, error) => { /* motion failed */ };
```

## Custom motions format

```json
{
  "my_motion": {
    "_description": "Human-readable description for LLM discovery",
    "_tags": ["emotion", "category"],
    "dt": [300, 2000, 500],
    "rescale": [0, 1, 0],
    "vs": {
      "mouthSmile": [0.6],
      "gesture": [["handup", null, true], null]
    },
    "_overlay": {
      "bones": {
        "RightHand": { "freq": 8, "amp": [0, 0.12, 0.12], "phase": 0 }
      },
      "delay": 400,
      "duration": 2500
    }
  }
}
```

- **`_description`**: Human-readable description (used by `getMotions()`)
- **`_tags`**: Semantic categories (used by `getMotions()`)
- **`dt`**: Keyframe durations in milliseconds
- **`rescale`**: Interpolation weights per keyframe
- **`vs`**: Viseme/morph target values + gesture commands
- **`_overlay`**: Optional bone oscillation overlay (frequency, amplitude, phase)

## Token cost analysis (theoretical)

> ⚠️ **Disclaimer**: The following analysis is a **rough theoretical estimate** based on character-to-token ratios. It has **not been validated** with actual tokenizer measurements and should **not be used as a reference** for production decisions. Actual token counts vary by model, tokenizer, and prompt structure.

When an LLM controls an avatar, every turn consumes tokens for context (system prompt + tool definitions) and output (the action itself). Here's a theoretical comparison:

### Context cost (input tokens per turn)

MotionEngine offers three verbosity levels via `getMotionsForPrompt()`:

| | TalkingHead native | ME `'full'` | ME `'compact'` ★ | ME `'minimal'` |
|---|---|---|---|---|
| System prompt | ~190 | ~660 | **~164** | ~103 |
| Tool definitions | ~250 (3 tools) | ~290 (1 tool) | ~290 (1 tool) | ~290 (1 tool) |
| **Total context** | **~440** | ~950 | **~454** | ~393 |

★ **Recommended.** The `'compact'` level groups motions by semantic category, giving the LLM enough context to choose correctly at roughly the same token cost as native TalkingHead.

### Output cost (tokens per action)

| Action | TalkingHead | MotionEngine |
|---|---|---|
| Simple expression | `😊` → ~2 tokens | `play_motion("wave_right")` → ~8 tokens |
| Gesture + expression | emoji + `playGesture()` → ~17 tokens | `play_motion("celebrate")` → ~8 tokens |
| Complex combo | `setMood()` + `playGesture()` → ~25 tokens | `play_motion("sigh")` → ~8 tokens |
| Sequence | ❌ not supported | `play_sequence([...])` → ~15 tokens |

### Expressiveness per token

| | TalkingHead | MotionEngine |
|---|---|---|
| Blendshapes per action | ~6 (face only) | ~8.5 (face + body + hands) |
| Layers per action | 1 | 4 (face + gesture + body + overlay) |

### Capabilities only in MotionEngine

- `chestInhale` (visible breathing) — used in `sigh`
- Multi-phase keyframed animations (5+ frames)
- Bone oscillation overlays (wave, dance, laugh tremor)
- Combined face + hand + body + overlay in a single call
- Jump arc via Hips position delta
- Motion sequencing (e.g., `smirk → eyeroll → sigh → dismiss`)
- `headMove: 0` / `eyeContact: 0` to disable auto-behaviors
